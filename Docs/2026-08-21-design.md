# HLSRemuxKit Design

## Goal

Provide a reusable iOS 16 Swift Package for lossless HLS media remuxing. The first release supports MPEG-TS input to MP4 output and local fragmented-MP4 HLS playlists to MP4 output. It never decodes or re-encodes media.

## Architecture

- `HLSRemuxCore` owns platform-independent command construction and remains testable on macOS.
- `HLSRemuxKit` owns the public async API and the FFmpegKitNext bridge.
- `Vendor/FFmpegKitNext` pins the 8.1.2 FFmpegKitNext-derived arm64 iOS binaries. The package also declares every dependent FFmpeg framework so consumers get a complete link set.
- A future self-built FFmpeg package can replace the vendor archives without changing the Swift API.

## API

`HLSRemuxer.remuxTS(input:output:progress:)` and `HLSRemuxer.remuxFMP4Playlist(input:output:progress:)` take local file URLs, create parent directories, and return an `HLSRemuxResult` with the output URL, byte count, and duration. `cancel()` cancels the active FFmpeg session. Progress is optional and throttling is left to the caller.

## Data flow and safety

The command uses `-map 0 -c copy`, with `+faststart` as a container-only relocation. Paths are passed as individual FFmpeg arguments, so spaces do not require shell quoting. Existing output is replaced only after FFmpeg has validated and opened the input. A failed or cancelled run removes its partial output.

## Testing

The first test layer verifies exact argument construction and the no-reencode contract on macOS. iOS simulator/device validation runs a real H.264/AAC TS fixture through FFmpegKitNext and checks that the resulting MP4 exists and exposes video and audio tracks.
